# plans

This directory contains project plans, timelines, milestone definitions, and stage-gate schedules for the BUS 629 portfolio. Plans answer *who does what by when* — they are the operational layer that sits between decisions (the *why*) and specs (the *how*).

Plans are living documents and are expected to change. When a plan is materially revised, append a brief change note at the bottom of the file with the date and the reason, so the trajectory of the project remains traceable.

## Naming conventions

- Project plans: `PLAN_[ProjectName]_[Phase].md` (e.g. `PLAN_DCFValuation_Stage1.md`).
- Timelines: `TIMELINE_[ProjectName]_[YYYY-MM-DD]_to_[YYYY-MM-DD].xlsx`.
- Milestone lists: `MILESTONES_[ProjectName].md`.
- Roadmaps: `ROADMAP_[Initiative]_v[N].md`.
- Reference BUS 629 stages explicitly in the phase slug: `Stage0`, `Stage1`, `Stage2`, `Stage3`.

## What goes here

- Stage-by-stage plans aligned to the BUS 629 syllabus.
- Milestone definitions with explicit completion criteria.
- Timelines, Gantt-style schedules, and dependency maps.
- Workstream breakdowns and owner assignments.
- Stage-gate / phase-gate criteria the work must satisfy to advance.

## What does NOT go here

- Decisions made during planning (use `docs/decisions/`).
- Technical specifications for what is being built (use `docs/specs/`).
- Progress updates after the fact — those belong in commit messages or status memos in `docs/`.
- Calendar invites, meeting agendas, or operational checklists.
- The actual deliverables produced by the plan (use `deliverables/`).
